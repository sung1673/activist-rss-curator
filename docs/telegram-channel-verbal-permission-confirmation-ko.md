## 2. 구두 승인 확인 선언

본인은 아래 각 채널의 운영자 또는 해당 이용을 승인할 권한이 있는 사람에게 BSIDE의 이용 목적과 범위를 설명했고, 기재된 일시와 방법으로 구두 승인을 받았음을 확인합니다.

- [ ] 허락자가 채널 운영자 또는 적법한 권한자인지 확인했습니다.
- [ ] 내부 수집·분석과 외부 공개·재배포가 다른 이용 범위임을 설명했습니다.
- [ ] GitHub Models 등 외부 AI 서비스로 콘텐츠 일부가 전송될 수 있음을 설명했습니다.
- [ ] 허락 범위의 변경·철회 방법을 설명했습니다.
- [ ] 체크되지 않았거나 채널 목록에 기재되지 않은 이용은 허용되지 않음을 확인했습니다.

## 7. SourceRight 등록 정보

```text
source_right_id: telegram:channel:<canonical numeric channel ID>
source_type: authorized_telegram
source_key: <@ 제외 소문자 handle>
source_name: <채널 표시명>
permission_scope: <허락된 scope 코드와 설명>
evidence_uri: physical://bside/telegram-permissions/<문서번호>
evidence_hash: <디지털 사본이 있을 때 작성 완료본 SHA-256, 물리 원본만 있으면 null>
valid_from: <시작 일시>
valid_until: <종료 일시 또는 null>
revoked_at: null
ai_allowed: true | false
redistribution_allowed: true | false
status: pending | active | expired | revoked
notes: <제한·철회·표시 조건>
```

- 내부 수집·분석만 허용된 경우 `redistribution_allowed=false`로 등록합니다.
- handle이 바뀌어도 같은 채널을 중복 등록하지 않도록 `source_right_id`는 Telegram numeric channel ID를 사용하고, 현재 handle은 `source_key`로 관리합니다.
- 외부 AI API 전송까지 허용된 경우에만 현재 외부 AI 처리 경로의 `ai_allowed=true`로 등록합니다.
- 원문·인용·이미지·RSS·API 재배포 항목이 명시적으로 허용된 경우에만 `redistribution_allowed=true`로 등록합니다.
- `evidence_uri` 또는 `evidence_hash`가 없는 권한은 `status=pending`으로 두고 처리하지 않습니다.

## 8. SHA-256 산출
